# Магазин: как продавать за реальные деньги

_Составлено 21.11.2026. Ставки и правила площадок меняются — перед подключением сверять с договором._

## 2. Три блокера, без которых деньги брать нельзя

1. **Нет подтверждения оплаты.** Любая покупка должна проверяться на сервере: «этот игрок правда заплатил 249 ₽ за 700 самоцветов?». Сейчас вся логика на клиенте — значит, любой школьник откроет DevTools и выдаст себе 4000 самоцветов. Для бесплатной игры не страшно, для платной — это дыра.
2. **Нет аккаунта.** Покупка должна быть привязана к чему-то живущему дольше кэша браузера. Иначе «я купил VIP, а он пропал» = возвраты и жалобы.
3. **Нет приёма денег.** Нужен либо эквайринг + сервер, либо платформа, которая берёт это на себя.

**Вывод: сначала канал (площадка или свой эквайринг), потом код.**

### Плюсы и минусы каждого

**Яндекс Игры — лучший первый шаг для этого проекта.**
- Игра уже один HTML5-файл, мобильная, без зависимостей — это ровно их формат. Переделывать почти нечего.
- Бесплатная публикация и бесплатный трафик: каталог сам приводит игроков. Для фермы в браузере это самое ценное.
- Их SDK закрывает сразу три наши дыры: авторизация (Яндекс ID), облачные сохранения, внутриигровые покупки. Сервер писать не надо.
- Реклама с вознаграждением (`rewarded video`) — это бесплатный аналог «посмотреть за 5 самоцветов». И вот тут товар «Без рекламы» наконец становится настоящим.
- Самозанятый: 6% налога, чеки Яндекс делает сам, выплаты раз в месяц на карту.
- Минус: доля платформы с покупок заметная, а правила запрещают уводить игроков на внешнюю оплату.

**Telegram Mini App — хороший второй канал.**
- Огромная аудитория, никакой модерации приложения, звёзды уже встроены.
- Минус: ~30% съедают, вывод в рубли через крипту (Fragment → TON → биржа) — лишнее звено.
- Минус: нужен бот и сервер для проверки платежей, свой трафик.

**RuStore — пока мимо.**
- С 1 февраля 2026 монетизацию для самозанятых и физлиц отключили: нет BillingClient/Pay SDK, платные приложения скрыли с витрины. Нужен ИП или ООО.
- Публиковать бесплатное приложение можно — но заработка не будет.

**Свой сайт + ЮKassa — максимальная маржа, но нулевой трафик.**
- 3,5% против 15–30% у площадок. На длинной дистанции это в разы больше денег.
- Но нужен сервер: принять вебхук, проверить чек, выдать товар, хранить владение по аккаунту. GitHub Pages статический — понадобится serverless (Yandex Cloud Functions / Vercel).
- И главное: игроков сюда никто не приведёт. Имеет смысл, когда аудитория уже есть.

## 4. Рекомендация

**Фаза 1 — Яндекс Игры.** Дешевле, быстрее, и решает проблему трафика и сохранений.
**Фаза 2 — Telegram Mini App.** Тот же файл, другая обёртка, второй источник игроков.
**Фаза 3 — свой сайт + ЮKassa.** Когда пойдут игроки, чтобы забрать маржу себе.

Итого: начать с Яндекс Игр, а архитектуру написать так, чтобы канал менялся одной строкой.

## 5. Что переделать в коде

**5.1. Один интерфейс на все каналы.** Сейчас `PUR_storeBuy(id)` — синхронная заглушка. Нужно:

```js
// Каждый канал реализует эти три функции, остальное — общее
const BILLING = {
  init(),                    // поднять SDK, авторизовать игрока
  buy(item),                 // вернуть Promise: {ok:true} или {ok:false, reason}
  restore(),                 // вернуть список уже купленного (важно при смене устройства)
};
```

- `BILLING_DEV` — текущая заглушка (мгновенная выдача). Остаётся для разработки.
- `BILLING_YANDEX` — `ysdk.payments.purchase()` + `getPurchases()`.
- `BILLING_TG` — инвойс в боте.
- `BILLING_WEB` — ЮKassa через свой serverless + вебхук.

Асинхронность обязательна: оплата занимает секунды, а игра всё это время не должна зависать.

**5.2. Владение покупками переносим с «устройства» на «аккаунт».**
Сейчас `S.pur.owned` лежит в localStorage. На площадке — брать из `getPurchases()` при каждом старте. Это защищает от «купил и потерял».

**5.3. Облачные сохранения.**
`save()` уже централизован — достаточно добавить один вызов в облако (Яндекс SDK это умеет). Закрывает давнюю боль: у игрока пропал прогресс.

**5.4. Профиль должен отражать прогресс, а не блокировать его.** После каждой покупки — перерисовка без перезагрузки, и понятный экран «что мне это дало».

## 6. Проблемы в текущем каталоге

1. **«Без рекламы навсегда» — фантом.** Рекламы в игре нет вообще. Либо сначала добавляем rewarded-видео (на Яндекс Играх это стандарт), либо убираем товар. Продавать несуществующее — прямой путь к возвратам и плохим отзывам.
2. **Цены не проверены на реальной аудитории.** 99 / 249 / 499 / 999 ₽ для браузерной фермы — верхняя планка. Для площадок типа Яндекс Игр и Telegram типичный чек ниже: имеет смысл добавить дешёвые входные позиции (49–79 ₽), чтобы человек «размочил» первую покупку. Первая покупка важнее её размера.
3. **VIP «на год за 3990 ₽»** для игры, где ещё нет аудитории, продаваться не будет — лучше убрать и вернуть, когда есть база.
4. **Продаётся сила, а не удовольствие.** В фермах лучше покупают: декор (красиво), скины зданий, ускорения на 10 минут, «пропуск сезона». Покупки, ломающие баланс, портят экономику и приводят к оттоку.

## 7. Порядок работ (после решения по каналу)

1. Ввести `BILLING`-адаптер, перевести `PUR_storeBuy` на него, оставить `BILLING_DEV` рабочим.
2. Подключить канал Фазы 1: SDK, авторизация, облачный сейв, список покупок при старте.
3. Добавить rewarded-видео как бесплатный путь к самоцветам (и как честную основу для товара «без рекламы»).
4. Пересобрать каталог под реальные цены и под то, что действительно покупают.
5. Аналитика: сколько доходят до витрины, сколько покупают, что не покупают вовсе. Без этого каталог — гадание.

### Итог одной строкой

**Начинать с Яндекс Игр**: игра уже идеально подходит под их формат, они дают трафик, аккаунты, облачные сейвы и приём денег, а самозанятости достаточно. Но перед этим — переписать магазин на асинхронный `BILLING`-адаптер, иначе любой новый канал потребует переписывать всё заново.
